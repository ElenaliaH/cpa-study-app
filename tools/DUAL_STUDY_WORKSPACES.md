# CPA / 税务师双备考空间：第一阶段

## 2026-09-14 发布更新

用户已授权生产备份、迁移、题库导入和推送。双空间迁移及税法一/税法二导入已在原Supabase项目完成；原CPA数据保留。详情见 `TAX_ADVISOR_BANK_REVIEW.md`。下文为第一阶段设计和验收记录，税务师题库已不再为空。正式切换后旧页面须刷新，禁止回退旧前端直接写入旧表。

## 当前范围

- 顶部只有一个备考空间切换按钮，在同风格弹窗内选择考试及年度。首页、学习计划、题库练习一起切换，并保留当前所在页面。税务师默认科目为税法一、税法二、涉税服务实务、涉税服务相关法律、财务与会计。
- 各空间独立保存考试日期、科目与轮次、手动任务、打卡、学习时长及日报。
- 新建年度可复制同考试的科目与轮次模板，不复制完成量、打卡、时长、休息日及旧截止日期。
- 年度可归档、恢复。归档不删除记录。
- 练习入口按考试选择科目与题库，保留客观题、主观题、顺序/随机、错题、收藏、笔记和继续练习入口。
- CPA 原题库保持原题 ID；税务师目前没有题库，等待用户验收空间后提供资料。没有复制或改名使用 CPA 题库。
- 当前阶段不提供税务师真实题目或真实 AI 回答；本地 AI 是原有演示适配器。

## 本地验收

在项目根目录运行 `npm start`。仅监听本机，不提供局域网访问。

预览：`http://127.0.0.1:3000/?taxDemo=1&workspacePreview=1`

这个地址显示“本地演示”，采用独立的模拟账号和本机数据，不连接正式学习数据。
不带 `taxDemo=1` 的页面会走真实账号和新版接口；数据库迁移尚未执行时，会显示“备考空间服务未就绪”，这是阻止错误写入的保护，不代表正式 Supabase 登录被修改。

1. 选择税务师，检查五个科目、倒计时日期设置、计划和计时功能。
2. 保存一次学习记录，切回 CPA，确认 CPA 中没有这条记录；再切回税务师确认仍在。
3. 计时中切换考试，原计时自动暂停；返回原空间可继续。
4. 新建下一年度并复制模板，确认旧年记录还在、新年完成量和时长为零。
5. 打开题库练习，税务师显示空题库；CPA 仍能进入原章节练习并保留答题进度。
6. 生成日报，标题包含当前考试和年度；未设置考试日期时不出现 NaN。
7. 归档年度后检查记录可查看、编辑被阻止；恢复备考后可继续修改。

## 数据契约

迁移草稿：`supabase/migrations/20260912032517_dual_study_workspaces.sql`。

- 新增 `study_workspaces`：账号、考试、年度、状态、原格式 data jsonb、revision、last_write_id、时间戳。
- 原 `user_app_data.data` 逐字复制到对应账号的 CPA 2026；原表与数据保留，不删除。
- 迁移在事务中锁定旧表完成复制，随后拒绝旧客户端写入旧表。正式发布需安排短暂维护窗口。
- 新增 `practice_banks` 元数据，已有题目和章节新增 bank_id，个人练习表新增 workspace_id；不修改原题干、答案、解析。
- 题库目录草稿新增稳定的 `subject_code`，数据库约束其必须属于对应考试。税务师五科代码为 `tax_law_i`、`tax_law_ii`、`tax_practice`、`tax_related_law`、`finance_accounting`，CPA 税法是不同的 `tax_law`。显示名称或同名章节不作为关联依据。
- 练习按考试、科目、题库逐层筛选；每个空间记住科目，每科分别记住题库版本。章节、进度、错题、收藏和笔记查询限定当前题库；没有题库的科目显示空状态，不回退到其他科目。
- 个人题目状态的唯一键改为账号 + 空间 + 题目，原年度的统计仍保留。
- 新空间由 RLS 限定账号读取，写入通过检查账号及 revision 的 RPC；读取失败不按空数据处理。
- 待上传数据保留原账号和空间。每个浏览器标签页有独立工作副本，冲突不静默覆盖；可导出恢复副本并明确选择本机/云端版本。
- AI 请求验证账号、空间和题库考试，次数配额仍按账号共享。密钥仍仅由服务器环境变量提供。
- JSON 计划备份新增 workspace 元数据，导入仅影响当前匹配空间。原备份未包含关系表中的刷题记录，本轮也不冒充全库备份。

## 发布边界

此分支尚未执行生产迁移、提交、推送或部署。不能单独推送前端后就视为云同步验收通过。

正式发布前需：

1. 用户先验收本地空间与入口，上传税务师题库后再做题库结构核验及导入。
2. 导出旧客户端未同步的本机学习数据，并对正式数据库做可恢复备份。旧浏览器缓存不自动认领给当前账号，避免串账号。
3. 在独立测试 Supabase 环境执行迁移，检查迁移前后用户、题目、打卡、时长、答题及收藏数量和关联 ID。
4. 用真实测试账号在手机、电脑两端验证登录、读写、离线重试和并发冲突。
5. 经确认后安排原 Vercel 项目的发布与数据库切换；不新建生产项目，不改 Worker。
6. 如需回滚，先保留新空间产生的全部数据，再制定兼容回迁。不可直接清空新表或仅恢复旧前端，否则可能丢失切换后的记录。

跨年度总览、题库版本映射调整、刷题全量导入导出和错题/收藏跨年携带的完整界面，后续随题库阶段继续验收，不作为本次空题库入口的已完成能力。

- `npm test`：现有刷题与 AI 模拟接口回归。
- `npm run test:workspaces`：空间模板、缓存隔离、离线恢复、乐观锁、RLS 和 SQL 迁移。使用内存 PostgreSQL（PGlite），不访问生产数据库。

- 本机 Playwright 使用 Codex 配套 Node 依赖目录，通过 NODE_PATH 提供；没有将浏览器自动化工具加入前端包。
